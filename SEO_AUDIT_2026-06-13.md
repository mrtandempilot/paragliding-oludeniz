## 🔴 Critical Issues (fix now)

### 1. `og:url` is wrong on every interior page
**What:** All pages except the homepage render `og:url: https://paragliding-oludeniz.com` (root). When someone shares `/tandem-paragliding` or `/prices` on Facebook/LinkedIn, the social card links back to the homepage instead of the actual page.

**Why it matters:** og:url tells social platforms which URL owns the content. Wrong value = link equity loss + bad UX for shares.

**Fix:** Add `url` to the `openGraph` object in every page's `generateMetadata()`. Example for tandem page:
```ts
openGraph: {
  ...
  url: localeUrl(locale, '/tandem-paragliding'),
}
```
Or add a helper in `lib/seo.ts` that returns a full openGraph block with correct url.

---

### 2. Blog page shows zero articles on the live site
**What:** `/blog` renders with only the hero section and an empty article grid. No posts are visible.

**Why it matters:** The blog is the primary organic traffic driver (AI content pipeline). If Google crawls /blog and sees no content, it won't index the articles and the whole content strategy is wasted.

**Root cause:** The Supabase query in `getArticles()` requires `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` at runtime, and falls back to `blogPosts` from `@/lib/blog`. If that array is empty AND Supabase connection fails/returns empty, the page renders blank.

**Action:** Check:
1. Do published articles exist in Supabase? (`SELECT COUNT(*) FROM articles WHERE status='published'`)
2. Are the env vars set in Vercel for production?
3. Is `lib/blog.ts` the fallback populated?

---

### 3. Meta description not overriding on interior pages
**What:** `/tandem-paragliding` renders `meta-description: "Book tandem paragliding flights in Oludeniz..."` — which is the homepage default from `layout.tsx`, NOT the page-specific description set in `generateMetadata()`.

**Evidence:** The page title IS correct ("Tandem Paragliding Ölüdeniz | Book from Babadağ"), proving the page-level metadata partially works — but description falls back to the layout default.

**Why it matters:** Duplicate descriptions across pages = Google may ignore them or suppress rankings.

**Fix:** In `generateMetadata()` for each page, also set `openGraph.description` explicitly. Next.js merges metadata and `og:description` doesn't automatically inherit from the page's `description` field unless openGraph is fully specified.

---

### 4. 104 non-locale pages redirect to `/` instead of locale equivalent
**What:** `app/about-us/page.tsx`, `app/tandem-paragliding/page.tsx`, etc. all contain `redirect('/')`. Any external link or bookmark to `/about-us` sends the user to the homepage.

**Fix:** Change each redirect to its proper English equivalent:
```ts
// app/about-us/page.tsx
export default function Page() { redirect('/about-us') }  // next-intl handles /en/ prefix
// OR
export default function Page() { redirect('/en/about-us') }
```

## 🟡 Warnings (fix soon)

### 5. Twitter card description is not page-specific
`twitter:description` shows "Soar over the Blue Lagoon. Book your tandem paragliding flight today." on all interior pages. Pages don't set `twitter.description` in their metadata, so it inherits from layout default.

**Fix:** Add to each page's `generateMetadata`:
```ts
twitter: { description: d[locale] || d.en }
```

### 6. `og:url` missing from prices page metadata
`/prices` fetch shows no `meta-og:url` at all (not even wrong). The generateMetadata for prices doesn't set openGraph.

### 7. Title template is effectively no-op
`layout.tsx` sets `template: '%s'` which just returns the title as-is. This means there's no consistent brand suffix. Some pages manually append "| Paragliding Oludeniz" and some don't. Inconsistent brand presence in SERPs.

**Fix:** Change template to `'%s | Paragliding Ölüdeniz'` and remove manual suffixes from page titles.

### 8. next-sitemap doesn't include hreflang alternates
The sitemap at `/sitemap.xml` lists URLs but doesn't include `<xhtml:link rel="alternate" hreflang="...">` entries for each locale version. Google recommends including these in the sitemap.

**Fix in `next-sitemap.config.js`:**
```js
alternateRefs: [
  { href: 'https://paragliding-oludeniz.com${path}', hreflang: 'en' },
  { href: 'https://paragliding-oludeniz.com/tr${path}', hreflang: 'tr' },
  ...
],
```

### 9. `robots.txt` generated twice (conflict risk)
`next-sitemap.config.js` has `generateRobotsTxt: true`, which regenerates `robots.txt` at build time. If there's also a `public/robots.txt`, they conflict — whichever lands in the build output wins. Verify only one source of truth.

### 10. Blog page inherits homepage meta description
`/blog` renders with the homepage default description instead of the blog-specific one set in `generateMetadata()`. Same root cause as issue #3.

### 11. ServiceSchema not on Prices or Book Now pages
`/prices` and `/book-now` — the two highest conversion pages — have no structured data. Missing opportunity for rich results.

**Fix:** Add `<ServiceSchema>` or `<Offer>` schema to these pages:
```json
{
  "@type": "Offer",
  "name": "Tandem Paragliding Flight",
  "price": "100",
  "priceCurrency": "EUR",
  "availability": "https://schema.org/InStock"
}
```

### 12. No Article/BlogPosting schema on blog posts
Individual blog articles need `BlogPosting` schema with `datePublished`, `author`, `headline`, `image`. This is required for Google News eligibility and article rich results.

## 🟢 Opportunities (nice to have)

### 13. Add Review/Testimonial structured data
Homepage shows 2,400+ reviews with 4.9/5. The `LocalBusiness` schema has `aggregateRating` — good. But adding individual `Review` entities (even 5-6 samples) would help rich snippets.

### 14. Add `EventSchedule` or `OpeningHoursSpecification` schema
The business operates April–October. Adding `openingHoursSpecification` to LocalBusiness schema signals seasonality to Google.

### 15. FAQ schema only on tandem page — expand
Pages like `/babadag-guide`, `/book-now`, `/prices`, `/solo-paragliding` all have Q&A content but no FAQ schema. Each eligible FAQ is a SERP expansion opportunity.

### 16. `preconnect` hints for Cloudinary and fal.ai CDN
Pages load images from Cloudinary CDN and fal.ai. Adding `<link rel="preconnect" href="https://res.cloudinary.com">` in the root layout would reduce connection latency for images.

### 17. Consider `PriceSpecification` for group discounts
The prices page mentions 10% off for groups of 4+ and 15% for 8+. These could be modeled in schema for richer results.
